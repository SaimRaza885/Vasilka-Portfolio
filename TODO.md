## Current multi-page scope

- [x] **Independent pages and simple navigation** — Build distinct Home (`/`), About (`/about/`), Projects (`/projects/`), Learning Journal (`/journal/`), and Contact (`/contact/`) pages, plus individual detail pages for ScamLens, Online Book Store — Kompas, LIMA, and Git Learning under `/projects/<slug>/`. Use ordinary working page links, an accessible mobile navigation and a shared minimal header/footer. Retain skills and education on About. Each project detail page must state only known facts and use the real matching repository link; do not invent outcomes, metrics, testimonials, deployments or project features. Do not fabricate journal posts; clearly show a calm empty/coming-soon state until genuine notes are provided.
- [x] **Clear, minimal redesign** — Preserve the existing editorial type, light neutral palette and restrained terracotta accent, while simplifying the layout for clear reading. Remove unnecessary decorative geometry, watermark text, abstract art, ornament, and decorative icons. Use concise page headings, readable text measure, generous but purposeful spacing, thin separators and text-forward project previews. Keep the hero portrait only as the single intentional hero visual, with clear fictional-AI disclosure; do not use it as unrelated page decoration.
- [x] **Dark mode** — Add a visible, keyboard-accessible text theme toggle. Support light and dark color tokens with readable contrast; remember a visitor's explicit choice and otherwise follow the device color-scheme preference. Keep page content and metadata independent of the selected theme, and avoid theme-switch layout shifts or a flash of the wrong theme.
- [x] **Per-page SEO and crawlability** — Prerender meaningful page-specific HTML for every route. Give every page a distinct, accurate `<title>` and meta description, and relevant social title/description. Use stable, descriptive URLs and semantic links; synchronize `client/public/manus-routes.json` with every public route. Ensure route content is present before client hydration and the build emits real nested route HTML.
- [x] **Performance and visual stability** — Preserve static serving and avoid unnecessary runtime dependencies or client-side work. Keep the initial visible content available in prerendered HTML, make the hero image discoverable and appropriately prioritized rather than lazy-loaded, defer off-screen project images where used, reserve media space with dimensions/aspect ratios, and minimize font/layout shifts. Aim to meet good Core Web Vitals in real-user field measurements; do not claim universal “no lag” or ranking guarantees.
- [x] **Responsive and accessible behavior** — Ensure every page reflows cleanly across small phones, tablets, and desktop without horizontal overflow. Use fluid images and layouts whose breakpoints respond to content. Preserve keyboard access, visible focus, semantic headings/links, readable contrast in both themes, and support for `prefers-reduced-motion`; remove large movement while keeping content visible and simple state feedback.
- [x] **Subtle site-wide motion** — Use only restrained page/section entrance or interaction feedback where it improves orientation or hierarchy. Keep hover behavior for fine pointers only, prefer composited opacity/transform for motion, avoid parallax/continuous effects/large zoom, and soften or remove positional movement under reduced-motion preferences.
